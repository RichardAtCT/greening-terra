# Decisions

Choices made where the spec was open or ambiguous. The rule is: pick what's closest to the prototype's behaviour and write it down here.

## M0: Pipeline

1. **Engine pinned to Godot 4.7.2** (latest stable at project start). `tools/setup_godot.sh` downloads exactly this version; bump `GODOT_VERSION` there and `config/features` in `project.godot` together.
2. **GUT rather than gdUnit4.** GUT 9.7.1 targets Godot 4.7 and runs headless with a single command (`-s addons/gut/gut_cmdln.gd`) and a proper exit code, with no extra runner or flags. It's vendored in `addons/gut/` and excluded from the web export.
3. **Where scripts live.** Section 7.2 doesn't say where Resource class definitions go, so they're in `scripts/data/` (the `.tres` values stay in `data/`). Scripts that belong to one scene sit next to it (`scenes/actors/player.gd`). Pure logic that tests and the balance sim call goes in `scripts/systems/` (e.g. `movement.gd`).
4. **UI units are CSS pixels.** Stretch mode is `disabled`, and the `DisplayScale` autoload sets `content_scale_factor` to the device pixel ratio. That makes the joystick exactly the prototype's size (112 px base, 46 px knob, 50 px travel) on any phone, while 3D still renders at full resolution.
5. **Joystick input.** Same as the prototype: the first touch anywhere spawns it, and only that finger drives it. Mouse drag also works on desktop (via `emulate_touch_from_mouse`), like the prototype's pointer events. Joystick and keyboard vectors are added together, then capped at full speed.
6. **Player is a `CharacterBody3D`** (floating motion mode). The prototype does its own circle push-out against buildings; using Godot's body now means building collisions in M1 need no extra code. The world-radius clamp (40 m) is kept.
7. **Physics interpolation is on.** The player moves in the physics step; the camera eases in `_process`, reading the interpolated transform, so it stays smooth on 120 Hz screens.
8. **PWA display is `standalone`.** iOS Safari doesn't support `fullscreen` in the manifest; standalone is what Home Screen apps get there. Status bar style is `black` (not `black-translucent`) until the HUD handles safe-area insets, so nothing sits under the notch.
9. **Download size.** The stock single-threaded web template's `index.wasm` is 39.5 MB raw, about 10 MB gzipped. The 40 MB budget (section 7.1) is treated as transfer size. If itch.io doesn't compress it, a custom template with unused modules stripped is an M6 performance task.
10. **Environment values in the test scene.** Sky colour, fog (near 14, far 48), sun and ground colour are set in `test_world.tscn` for now. They move into the `PlanetDef` palette in M1, when terraform % starts driving them.

## M1: Prototype parity

11. **Sim and view are separate.** `GameSim` (`scripts/systems/`) owns every rule and has no scene access; `scenes/world/planet.gd` only feeds it the player's position and draws its state. The balance sim and tests drive the same `GameSim`.
12. **Drone routing is still the prototype's**: each hauler takes route `index % routes`. SPEC 4.5's dispatcher replaces it in M4, as planned.
13. **Planets 2 and 3 already exist, but only as re-skins**: the prototype's palettes and its pay/terraform multipliers, on Planet 1's layout. That keeps the prototype's "launch to the next world" flow working until M5 adds the real content. As in the prototype, after the third planet the list repeats with a numeral ("Tessera-4 II").
14. **Planet data files.** Machines, nodes and the tutorial are separate `.tres` files shared by all three planets, so a tweak lands everywhere at once.
15. **Pads show text, like the prototype.** SPEC 6's item icons on pads are an art task for M3.
16. **World labels always draw on top** (no depth test), and the panel behind them is a rounded-rectangle shader. The prototype's canvas sprites could be hidden behind buildings; these can't, which reads better on a small screen.
17. **Frame time is capped at 0.05 s** for the sim, as in the prototype, so a stall never skips a whole transfer chain.
18. **Recipe input order** comes from Godot's dictionary sort, so the greenhouse label reads "O₂ · Plate" rather than the prototype's "plate · O₂". This is cosmetic.
19. **Draw calls.** Each resource node, drone and the greenhouse seedlings are merged into single meshes, and item stacks use one MultiMesh per item type. A late-game Planet 1 has about 150 drawables before frustum culling. The real iPhone frame rate still needs checking on a device.
20. **Seedpods have a food value of 1** already, so M4's colonists have data to read.

## M2: Data, saves and balance sim

21. **Terraform values were cut to about a tenth of the prototype's**: plate 0.15 → 0.018, O₂ 0.4 → 0.045, seedpod 1.6 → 0.08. Played greedily, the prototype's economy finishes Planet 1 in 5 min 20 s. SPEC 3 says those values were "to be tuned by the balance sim". With the new values the bot finishes in about 29 min. A child will be slower than a greedy bot, so this errs short. Plates and O₂ were cut less than seedpods, so the planet visibly changes before the greenhouse is built.
22. **Late-game credits pile up.** The bot ends Planet 1 with thousands of unspent credits once pack, boots and 12 haulers are maxed. SPEC 4.4's extra sinks (dig speed, hauler capacity, machine level-2 pads) will soak this up. Re-run the sim when they land.
23. **Planets 2 and 3 are `balance_enforced = false`** until M5 gives them their real chains. The sim still reports them.
24. **The bot's buying rule**: pick the affordable purchase with the best value per credit (buildings 3, haulers 2, pack 1.2, boots 1), but don't spend on kit once the next building is half-affordable. It then feeds before selling, collects piles of three or more, and digs whichever raw resource the chain is shortest of.
25. **Defaults live in the resource scripts, values in `.tres`.** Godot leaves unchanged values out of `.tres` files, so `data/game_tuning.tres` looks empty but holds all the prototype's numbers. Edit them in the Inspector. Anything changed from the default is written into the file.
26. **Text entry on web uses the browser's `prompt()`**, for names, backup and restore. Godot's own text fields don't open the iPhone keyboard. Backup text is `GT1:` plus base64-encoded JSON.
27. **A new game is saved as soon as it starts**, so the title screen shows "Continue" straight away. Autosave counts real time, not the capped sim step, so slow devices still save every 10 s.
28. **Erasing a profile needs a second tap**, the same pattern as "Restart planet". Nothing destructive happens on one tap.
29. **Audio buses and volume settings exist before any audio does.** The Music and SFX buses and their sliders are wired up now; the sounds arrive in M3.

## M3: Planet 1 art pass

30. **Models are baked into single meshes.** Every Kenney material is a flat colour, so `tools/dev/bake_models.gd` merges each model's surfaces into one surface, with the colours moved into vertex colours (`assets/materials/kit.tres`). Glass goes into a second, transparent surface (only the greenhouse has one). Each building is one draw call plus its glow, and each drone, resource node and decor MultiMesh is one. The bake recentres every GLB on its bounding box, with its base at y = 0; the files were offset by (2, 0, 1.5).
31. **The bake's placements live in the tool, not in `data/`.** Scales, offsets and recolours are art authoring, like a model file, not gameplay tuning. Re-run the bake after changing them. The placeholder generator is deleted, since running it would overwrite the new scenes (git history keeps it).
32. **Space Kit colours are warmed and darkened** (`PALETTE` in the bake tool). Its near-white greys blew out under the planet's late-game light and looked cold next to the rust ground. The new values follow the prototype's hub palette.
33. **The astronaut is Kenney's astronautA, recoloured.** It's bare-headed, so its hair became a white helmet and its face the prototype's orange visor. An orange backpack box was added for the back stack. Body (with arms and head) and the two legs are three meshes, so `PlayerController` still bobs them. It now stores their rest positions instead of assuming the capsule's.
34. **Resource nodes and decor are tinted at runtime.** Their baked vertex colours are greys, multiplied by `ResourceNodeDef.color` or the ground colour. So data still decides the look, and the planet 2 and 3 re-skins recolour automatically. Ice nodes are Kenney's crystal rock plus five procedural shards. They're opaque now (`translucent` only affects the procedural fallback), which avoids sorting problems.
35. **Ground moss is a shader front, not per-triangle.** `ground_terraform.gdshader` tints the ground from `ground_start` to `ground_end` and blends in `PlanetDef.moss_color`. It uses a ragged front whose distance from the hub follows the middle of the moss patches' thresholds (`TerraformView.moss_reach`), so the ground and the patches green together. Two value-noise octaves in world space give the edge and the patchiness, with coverage rising from 35% to 95% between 15% and 85% terraform. The per-triangle shade in vertex colour keeps the faceted look.
36. **Lakes are a faceted, gently heaving disc.** The water shader moves the inner vertices of a ring-subdivided unit disc (the rim stays on the ground). It flat-shades with screen-space derivatives and adds drifting light streaks and a foam rim. It's opaque, so there's no sorting.
37. **Two tree kinds and new grass and flower layers.** Pines (60%) and round trees are two MultiMeshes. Grass tufts spread from 40%, and flowers open from 70%, the same point birdsong starts. That's +3 draw calls, paid for by the merges above. Moss patches are smaller and darker now that the ground itself turns green.
38. **Pad icons float above each pad's far edge** and turn slowly: the recipe's inputs on IN, the output on OUT, everything sellable on DELIVER, and a gold coin on every pay pad. They use the item's own mesh and colour. `PadInfo.icons` is display data set by `GameSim` next to the existing title and label. No rule changed.
39. **The wind is a generated WAV loop, not an `AudioStreamGenerator`.** At start-up, 4 s of low-passed noise is generated with a crossfaded seam. Pitch and volume are then set per frame (falling as terraform rises, with slow gusts). That's the same sound without pushing samples every frame, which would stutter on a slow phone or a background tab. Birdsong is five generated chirp calls, played at random from 70%. Both are on the Music bus. The planet scene starts them, so the title's Start tap has already unlocked iOS audio.
40. **Sound choices.** Pick-up is a pluck whose pitch climbs with the stack. Drop is a soft drop, and every delivery (drones' too) is a coin tick. Digging is only heard near the player. There's a chime for a building and another for an upgrade, a fanfare for the win, and an engine rumble on "Launch". Each sound has a minimum repeat interval, so twelve haulers don't machine-gun the tick. Buttons click. The lander sound plays on launch for now; M4's landers can reuse it.
41. **Juice** (all off with "Fewer effects"): the item that lands on the back stack bounces. A finished building springs up from 55% height with a squash and a dust puff, and the camera punches in along its offset and springs back. Confetti falls at 100%. The numbers are in `data/juice.tres` and `CameraTuning`.
42. **Draw calls.** A late-game Planet 1 (everything built, 12 haulers, 20 carried, 100%) counts 143 visible surfaces before frustum culling (`tests/smoke/test_art_pass.gd` keeps it under 150). The build transfers about 11 MB gzipped: the pack is 0.8 MB, and the source GLBs are excluded from the export.

## M4: Colonists, hazards and dispatcher

43. **The dispatcher scores jobs as SPEC 4.5 says, with the weights in `GameTuning`.** A job's score is how empty the target's queue is (× 10), how full the source's OUT pad is (× 12), how full a hold it fills (× 4), a bonus for carrying goods on to another machine rather than selling them (+3), minus metres flown (× 0.12). A full OUT pad stops its machine, so it outranks an empty queue at the same distance. On its own, the dispatcher kept the balance sim within a few seconds of the old `index % routes` (29:13 against 29:19).
44. **Reservations are read off the haulers, not kept in a table.** Each hauler holds its job and how many items it still has to pick up. "Reserved at this OUT pad", "reserved in this node" and "on the way to this queue" are sums over the (at most 16) haulers. Nothing can go stale when a job is dropped. A finished hauler takes its next job in the same step, so none sits idle for a frame while work exists (the Dispatcher tests check both).
45. **Haulers with nothing to do hover in a ring by the Drone Bay** and ask again every step. A hauler that finds its node emptied flies to the next one; if the target queue has filled up (the player fed it), sellable goods go to the hub after `drone_unload_wait`, as before.
46. **Colonists walk in straight lines and slide round buildings, with no NavigationAgent3D.** SPEC 4.1 allowed a navmesh, but the ground is flat and every obstacle is a collision circle. Pushing out of circles, plus a sideways step when walking straight into one, gets them everywhere. It's pure code, so the balance sim includes the walking.
47. **Where colonists work.** Each built machine takes up to two, one on each side, a little towards its pads. They're spread one per machine before doubling up, and keep their machine for good (machines never unbuild). On Planet 1 that's six working and the rest off duty, strolling near their habitat. Machine level-2 pads (SPEC 4.4) will give later colonists more to do.
48. **Food.** Each colonist has a meal timer; at zero they eat one meal from the hub's store, or go hungry (stop working, show a pod icon) until food arrives. Seedpods (food value 1) fill the store until it holds `food_reserve_seconds` (300 s) of meals for everyone housed, then sell as normal. **A stored pod still adds its terraform %**, so feeding the colony slows only credits, not the planet. Colonists don't eat while waiting for a habitat.
49. **Habitats.** Three plots south of the hub, holding four each. The first is free and built by the first lander (SPEC 4.1). The next two cost ₵120 and ₵240, and each BUILD pad appears only once the previous habitat stands, so a child isn't shown three things to buy at once. Colonists with no room wait by the landing pad and move in when a habitat is built. Positions, costs and the landing pad are in `PlanetDef`; the rest is in `ColonyTuning` (`data/colony_tuning.tres`).
50. **Landers.** One per milestone, one at a time: a lander appears when terraform passes the next milestone and touches down `lander_descent_time` (5 s) later. A save from before M4 loads with no landers, so the ones already due arrive one after another. The lander's stay and lift-off are view-only. The existing engine sound plays as it comes down, and a metal thud on touchdown.
51. **The dust storm is `HazardDef` + `HazardDirector`**, the framework SPEC 4.2 describes. Between 15% and 60%, it waits 4–6 min (the gap grows by up to 1.5× towards 60%), warns for 10 s, then blows for 30 s: player −30%, haulers −40%. The random gap is seeded from the planet seed and the storm count, so saves and the balance sim repeat exactly. A storm that has started finishes even if terraform passes 60%. Planets 2 and 3 (still re-skins) have no hazard until M5 gives them theirs.
52. **Storm look.** During the warning the sky darkens and the sun dims. Then an orange fog rolls in (fog from 13 m to 32 m from the camera, which sits about 17 m from the player, so the area round the astronaut stays readable), the dust motes thicken and race sideways, and the wind loop gets louder and higher. The dust shader now takes the wind's accumulated drift from the CPU instead of `wind × TIME`, so the wind can change speed without the motes jumping. "Fewer effects" skips the lander's dust puff; the storm's fog stays because it's the warning.
53. **Terraform values are 0.75× M2's** (plate 0.0135, O₂ 0.034, seedpod 0.06). Colonists' +25% per working colonist made the machines faster, and the balance sim finished Planet 1 in 23 min. Scaling every value keeps DECISIONS #21's proportions and brings it back to about 30 min. The storms cost the greedy bot only seconds.
54. **Colonist models are Kenney Mini Characters**, four of them (one MultiMesh, so one draw call, each). They're rigged and textured with a colour atlas, so the bake tool poses the skeleton at the first frame of `idle` (arms down, not the bind T-pose), skins the vertices on the CPU, and samples the atlas at each vertex's UV into vertex colours. That keeps them in the one shared vertex-colour material. The walk is a procedural waddle (bob and sway), and working is a nod towards the machine. The GLBs reference `Textures/colormap.png` rather than embedding it.
55. **The lander is three Space Kit rocket parts** (`rocket_baseA`, `rocket_fuelA`, `rocket_topA`) and the habitat is `hangar_smallB` with a small dish and a lit window. Both are baked like the other buildings.
56. **Draw calls.** All haulers share three kinds of MultiMesh (hulls, shadows, one per cargo item), and every pad's base slab and floating icons are batched into a few more (`PadBatch`). That frees about 35 calls. `tests/smoke/test_art_pass.gd` now counts the worst case: everything built, 12 haulers with mixed cargo, the full colony with some hungry and two waiting, a lander coming down and a storm blowing. That's 131 surfaces before culling (budget 150). With culling, the debug overlay reads about 96 in a normal mid-game view.
57. **The debug overlay** toggles with F3 or the backtick key, or with "Debug overlay" in Settings for touch devices. It draws each hauler's job as a line (amber: field, cyan: machine to machine, green: to the hub; darker while flying to the source) and a faint line for each walking colonist. A panel shows fps, draw calls, every hauler's job, the colony and the hazard timer.
58. **New sounds, picked by name and not yet heard:** a bong for the storm warning (Interface Sounds `bong_001`), a light glass chime when a pod goes into the food store (`glass_002`), and a metal impact on touchdown (Sci-fi Sounds `impactMetal_002`).

## Balance: the mid-game had nothing left to do

59. **Machines can be upgraded (SPEC 4.4), up to Mk IV.** Played by hand, six haulers at about 10 minutes kept the chain running on their own: from there the Greenhouse, not the player, set the pace. The balance sim showed it: a bot that stood still once it had eight haulers finished only 5 minutes behind one that kept playing, and the last haulers (up to ₵3,200 each) sped nothing up. Each machine now has an UPGRADE pad beside it: +50% speed and +10 OUT pad space per mark, three marks (Smelter and Electrolyser ₵120 / 300 / 700, Greenhouse ₵200 / 500 / 1,100). Faster machines need more haulers to feed them, so haulers and upgrades take turns being the best buy until about 28 minutes. SPEC only asked for a level 2; three marks give the late game somewhere to spend. Costs, speed and pad position are in each `MachineDef`.
60. **UPGRADE pads appear once the whole chain stands** (the Greenhouse is built). With them open from the start, the bot spent early credits on a Smelter it couldn't keep fed and finished 20 minutes late; a child would do the same. A tutorial step after the Greenhouse points at its UPGRADE pad, since it's the slowest machine.
61. **The bot values an upgrade by how backed up that machine's queue is**, so it upgrades the bottleneck, not whatever is cheapest. Planet 1 still finishes in about 30 minutes, so the terraform values are unchanged.
62. **The game says how colonists come.** Landers are called by terraform %, but nothing on screen said so. The HUD's colony panel now shows from the start with "lander at 10%" (then 25%, 40%...), the objective bar starts with "At 25% a lander brings 2 colonists." (or "2 colonists need a Habitat.") once the tutorial is done, and the lander toast names the next milestone.
63. **Haulers are capped at 8 on Planet 1, then upgraded instead.** Past about eight, each extra hauler cost more (up to ₵3,200 for the 12th) for the same small gain, and a dozen crossing the screen is hard for a child to follow. Once the whole chain is built, a HAULERS pad beside the Drone Bay's BUY pad upgrades every hauler at once, alternating +1 cargo and +15% speed (six levels, ₵250 then ×1.7 each; the amounts are in `GameTuning`). This extends SPEC 4.4's "capacity +1, 3 levels". Each level makes every hull 6% bigger, so it shows. The BUY pad goes once the cap is reached. Planets 2 and 3 keep 16 until M5. The bot values a hauler upgrade as the haulers it improves times how much it improves each.
64. **Terraform values are 0.8× #53's** (plate 0.0108, O₂ 0.0272, seedpod 0.048). With machine and hauler upgrades the greedy bot finished Planet 1 in 25 minutes with everything bought by 23. At 0.8× it finishes in about 29–30 minutes, with a purchase every one to four minutes until about 28.
65. **A pay pad rests for 2 s after a purchase** (`GameTuning.pay_rest`) and dims while it does. Before, a pad started draining credits for the next level straight away, so a player still standing on an UPGRADE, HAULERS, PACK or BOOTS pad bought a second level before they could step off. Standing on it past the rest still buys again, so buying several levels in a row still works. The rest isn't saved, since a reload can't double-buy.

## M5: Planets 2 and 3, star map, bonuses

66. **Each planet has its own chain and tutorial.** DECISIONS #14's shared files stay for the Smelter and Electrolyser, which are the same everywhere. A machine that differs gets its own file: Orrin b's Greenhouse (`greenhouse_orrin.tres`, plate + O₂ + polymer) keeps the id `greenhouse`, so a placeholder save's built flag and queues carry over. Each planet has its own `TutorialDef`.
67. **Heat Towers are machines with a `heat_radius`.** Each burns 1 polymer every 6 s and has an IN pad but no OUT pad, so haulers feed them like any machine (the dispatcher skips output jobs for a machine that makes no item). While one burns, machines within 9 m of it keep full speed through a cold snap. Each burn also adds 0.05% terraform (before the planet's divisor), straight to the planet, so polymer has a use between snaps and "heat warms the planet" is literal. There are three fixed plots (₵60, ₵90, ₵120), each covering two machines, and the player picks which to build first. Towers take no colonists, have no upgrades and ignore Overclock, so none of those can make them burn polymer faster.
68. **The cold snap** comes every 3 to 4.5 minutes between 8% and 85% (the gap grows to 1.3×), warns for 10 s and lasts 45 s. Machines outside a burning tower's radius run at 50%. It looks like snow (the dust motes turn white and fall), a pale blue fog, frost back on the ground, and a frost overlay on every machine it slows. Its warning is Interface Sounds `glass_004`.
69. **Orrin b's look.** Frost covers the ground at first. It melts back from the hub as terraform rises, is gone by 55%, and never forms round a burning tower. Sparkles of ice keep it from reading as fog. The sky goes violet night → teal → blue, and the lakes are meltwater blue. Tundra comes before forest: grass 15% earlier, flowers 5% later, trees 15% later, the plants yellower and less saturated, and 90% of the trees pines. These are new `PlanetDef` fields (Surface and Vegetation groups).
70. **Kessik's toxicity caps terraform, but nothing delivered is lost.** Deliveries add to the planet's *growth*. Terraform is growth capped at 100 − toxicity, so on arrival (100% toxic) the planet shows 0% whatever you deliver. Each filter delivered clears 0.08% toxicity (1,250 in all) and sells for ₵1. As the toxins clear, the banked growth shows. This answers SPEC 11's question: the cap stays, but it holds progress back rather than wasting it, which suits pillar 4. The HUD shows a toxicity bar under the terraform bar and shades the part of the bar the toxins still hold back.
71. **Geothermal vents power what's built on them.** A machine within 1.5 m of a vent runs 50% faster. Kessik's three new machines (Scrubber, Ice Melter, Algae Pond) sit on its three vents, which is what the tutorial tells the player. Each vent has a dark crater and steam that rises, swells and fades on the GPU (one MultiMesh for all of them). The heat shimmer is that steam haze. A real screen-distortion shimmer would copy the screen every frame, too costly on a phone.
72. **Meteor showers** come every 6 to 8 minutes between 5% and 95%. When the 5 s warning starts, the impact points are chosen and marked with pulsing red targets on the ground: one on a machine, two on open ground round the colony. It is seeded, like every hazard gap. A meteor never hits the hub, a Heat Tower, or the machine that makes the repair item (the Smelter), so a repair is always possible. The meteors fall for 2.5 s with fiery trails. When they land, the machine they hit stops: it keeps its queue and can still be fed and emptied, but makes nothing. It shows soot and smoke, and a REPAIR pad appears in front of it. Standing on the REPAIR pad with plates on your back moves them in one per transfer tick, and at 5 it's fixed. Haulers never repair. Sounds: Sci-fi Sounds `forceField_001` for the warning and `lowFrequency_explosion_000` for the impact. The camera nudges and dust bursts at each impact, both skipped with "Fewer effects".
73. **Biomass is Kessik's food, and Kessik has no Greenhouse.** Its top product is the Algae Pond's biomass (O₂ + water, where the Ice Melter turns ice into water). The colony eats whatever food item the planet makes, and the hungry icon over a colonist's head follows it.
74. **Bonuses** are `BonusDef`s (a kind and an amount) in `data/bonuses/`. At 100% the win screen offers three the player hasn't taken, picked at random but seeded from the planet and the number already taken, so a reload offers the same three. One pick per planet. Bonuses carry over with the pack, boots and dig speed. Head Start gives every later planet a Drone Bay and one hauler. Big Lander grows the habitats in step (4 → 8), so the extra colonists aren't left waiting. Weather Shield shortens every hazard by 30%, which on Kessik only shortens the meteors' fall, so it's the weakest pick there. The pool has eight, so after three planets five are left for the next round.
75. **The star map replaces "Launch to …".** After the bonus pick, "To the star map" opens it: the three worlds on a line, finished ones ringed in green, and the rocket parked above the current one. "Launch" flies the rocket along an arc (2.2 s, `GameTuning.star_map_flight_time`) and lands on the next world. After Kessik it loops back to Tessera-4 II, as before. "Stay here" on the win screen now has a way back: once a planet is won, the menu has a Star map button, and if the bonus wasn't picked, it offers the pick first. **Free-play revisits of finished planets aren't built.** They'd need a second save slot per planet, and SPEC 11 still has them as an open question.
76. **SPEC 4.4's upgrades, merged with #59 and #63.** Machine upgrades (Mk II to IV) and hauler upgrades are #59 and #63's. The new machines get their own marks: Refinery ₵240 / 600 / 1,300, Scrubber and Ice Melter ₵160 / 400 / 900, Orrin b's Greenhouse ₵300 / 700 / 1,500, Algae Pond ₵400 / 900 / 1,800. Heat Towers have none, and don't count towards "the whole chain stands" (#60), since they're placement rather than chain. Two things are added:
    - **Dig speed** is a third Outfitter pad (+15%, 5 levels, carries over from planet to planet), so the Outfitter's pads moved to −2.4 / 0 / +2.4 m.
    - **An upgraded machine takes two more colonists** (four in all), standing behind the first two. That gives Planet 1's six off-duty colonists work.

    An UPGRADE pad hides while its machine is meteor-damaged. The REPAIR pad sits in a second row in front of the IN and OUT pads, where nothing else is. M5 first had its own single level-2 upgrade and a HOLD pad; #59 and #63 replace both.
77. **Balance.** All three planets are now `balance_enforced`. The greedy bot got four changes. It keeps digging nearby rocks of the same kind until its pack is full (before, it stopped when one node emptied, so pack upgrades and Deep Pockets did nothing for it). It fetches plates and repairs a damaged machine before anything but buying. It values dig speed at 0.6 (machine and hauler upgrades are valued as in #61 and #63). It picks bonuses in a fixed order (Overclock, Swift Haulers, Trade Charter, …), and the sim carries its kit and bonuses from planet to planet. The planets' terraform divisors are 1.0, 2.05 and 2.7, and Kessik pays ×1.6 rather than ×2. Planet 1 keeps #64's values: with dig speed and the bot's fuller pack it still finishes in about 30 minutes. Result: 29:36, 41:22 and 50:42, against targets of 25–35, 35–45 and 45–60. Hazards cost the greedy bot fifteen seconds at most (`--no-hazard`): it builds Heat Towers early and repairs in seconds. A child will feel them more, as with the dust storm (SPEC 11). With #59 and #63's upgrades the bot keeps buying until late; it ends with ₵0.8k, ₵6.7k and ₵7.7k unspent, down from ₵15–32k on the placeholders.
78. **Save version 3.** It adds growth, toxicity, bonuses and the pick, the dig level, meteor damage, repairs and impact points (#59 and #63's machine and hauler levels load as 0 when missing, so they need no step). Migrating from version 2 sets growth to the saved terraform and fills toxicity from the planet, capped so an old save's % never drops. Growth and toxicity are rounded to 9 decimals as they change. Godot writes 16 significant digits to JSON, and without the rounding a save sometimes came back a hair different.
79. **Draw calls.** Planets 2 and 3 have more buildings and pads, so three things are batched:
    - Every pad's top, title and subtitle are one MultiMesh reading a text atlas. The atlas is built on the CPU: the TextServer shapes each string and its glyphs are copied from a plain (non-MSDF) copy of the font. Drawing Labels into a SubViewport and reading that back came out garbled on WebGL.
    - Building labels are drawn in 2D by `LabelLayer`, in three passes (panels, titles, subtitles).
    - Resource nodes are one MultiMesh per resource (`NodeBatch`).

    The worst cases (everything built and half levelled, max haulers with mixed cargo, the full colony, a lander, the planet's hazard at full strength, and on Kessik a damaged machine) are now 67, 85 and 85 against the budget of 150. Planet 1's was 131.
80. **Two web-only faults, found in headless Chromium.** MultiMesh instance data can arrive as 11.999, so the pad shader rounds the atlas cell index. The ground's faceted bumps could reach above the pads, and on a 16-bit depth buffer (which headless Chromium has) they showed through. Inside the play area the terrain now only dips below y = 0, and pad tops are drawn a fraction nearer the camera along the view ray.
81. **New sounds, picked by name and not yet heard:** the cold snap's `glass_004` and the meteor warning `forceField_001` (see #68 and #72), a heavy `lowFrequency_explosion_000` for the impact, Impact Sounds `impactMetal_medium_000/001` for each plate going into a repair, and Interface Sounds `confirmation_001` for picking a bonus. `Audio.stop_all()` exists so tests can stop everything before exit; that also cleared the old "ObjectDB instances leaked" warning.

## Balance: plates and O₂ early on

82. **The Greenhouse has a SWAP pad until Mk II.** Planet 1's Greenhouse needs a plate and an O₂ each cycle, but its IN pad takes whatever you carry, and a child won't bring them one for one. O₂ is the side that runs short: ice rocks hold 5 to regolith's 6, there's one fewer of them, and the Electrolyser has to be bought. In the balance sim, a player who mostly digs regolith left the Greenhouse idle for want of O₂ for 70 s of its first 10 minutes, and a player who dug at random for 43 s, while their spare plates sold for ₵2. The SWAP pad sits on the Greenhouse's left, opposite its UPGRADE pad. Standing on it trades 2 of the input you have more of for 1 of the one it's short of, onto your back, counting what's in the Greenhouse's queue and what you carry. It stops before swinging the other way, so 8 plates become 2 plates and 3 O₂. Each trade takes two transfer ticks, and the items fly both ways. The pad's text is a fixed "2 FOR 1" with both icons, since a changing subtitle redraws the whole pad atlas. While the Greenhouse sits idle, missing an input the player could swap for, the objective bar says so ("Out of O₂? Swap 2 plates for 1 O₂ on the SWAP pad."). The pad goes at Mk II (the tutorial's next step), when haulers and upgrades carry the chain. Haulers never swap: the dispatcher already balances what they carry. The ratio, the level it goes at, where it sits and the hint are in `MachineDef` (`swap_ratio`, `swap_until_level`, `swap_pad_offset`, `swap_hint`). Only Planet 1's Greenhouse has one. The bot swaps only when the Greenhouse is about to run out (under 3 of an input queued), so its surplus still sells otherwise. With it, the regolith-only player's O₂ gaps fall from 70 s to 43 s and the random digger's from 43 s to 18 s. The greedy bot finishes in 29:28, much as before (41:22 and 50:42 unchanged), so no terraform values moved.

## M5 follow-ups: the web build and pad costs

83. **Two Godot 4.7 export faults hid the UPGRADE pads on the web.** On the web build no machine had upgrade costs, so no UPGRADE pad existed, and the tutorial's guide circle pointed at an empty spot. Kessik's vents were lost the same way. The editor, the tests and the desktop screenshots all saw the data, so nothing caught it. There were two causes. A packed-array export declared with an empty initializer (`= []`) comes out empty in exported builds when a `.tres` sets it; a non-empty default exports fine. And the exporter's conversion cache (`.godot/exported`) isn't redone when only a resource's script changes. `MachineDef.upgrade_costs` and `PlanetDef.vents` now have no initializer. `tools/export_web.sh` clears the cache before every export. `tests/unit/test_data_export.gd` fails if a data file sets a packed array declared with an empty initializer. A property-by-property dump of every `data/` resource now matches between the editor and the exported pack.
84. **Every buy-again pad shows its next cost.** Before, only UPGRADE and HAULERS pads (#59, #63) showed one; the pack, boots, dig and hauler pads showed only what they add. The Outfitter's label listed pack and boots costs but not dig. Now PACK, BOOTS, DIG and DRONE pads read like the upgrade pads ("+4 SLOTS ₵45", "+15% SPEED ₵30"), updated as levels are bought. The Outfitter's label no longer repeats the costs; it says "kit that travels with you". Once the hauler cap is reached, the Drone Bay's label shows the next hauler upgrade's cost.
85. **On web, saves are also kept in localStorage.** Saves were lost on itch.io: a player who switched apps or closed the tab came back to an older game. Godot writes `user://` to an in-memory file system and copies it to IndexedDB only at the start of its next frame. A hidden page draws no frames, so the save made on `visibilitychange` stayed in memory, and if the browser then closed the page (iOS often does), up to 10 s of play, or a purchase, was gone. A test that hid and froze the page confirmed it: the save ran, but IndexedDB kept the previous autosave. `SaveManager` now also writes every file to localStorage (keys `greening-tessera/profile_N.json` and so on, since every itch.io game shares one origin), which is written at once, and reads that copy first. If writing it fails, the key is cleared, so an older copy is never read over the file. Saves that exist only in IndexedDB still load, and are copied over at the next save. The old `_sync_web()` did nothing: Godot 4 doesn't make `FS` global. If the browser keeps neither IndexedDB nor localStorage (storage blocked, some private windows), the title screen says progress won't last and points to Back up save.
86. **The iPhone plays the game from Netlify, not itch.io.** #85 closed the save-on-hide gap, but on itch.io the game runs in an iframe from `html-classic.itch.zone`, a different site from `itch.io`. WebKit makes a cross-site iframe's localStorage and IndexedDB ephemeral: they go when Safari quits, and every iOS browser is WebKit. The Storage Access API in Safari unlocks only cookies, itch.io has no setting that removes the iframe on mobile, and the direct itch.zone URL changes with every upload, so it can't be a Home Screen bookmark. So each green `main` build is also published to an unlisted Netlify site, where the game is the page itself and its storage stays. As a Home Screen app it also skips Safari's 7-day data deletion. Cloudflare Pages was the first choice, but it caps each file at 25 MiB, and `index.wasm` is about 38 MiB. The site ID is a GitHub secret, since this repo is public, and every response carries `X-Robots-Tag: noindex`. itch.io stays for desktop play, and Back up save stays the safety net.
87. **The Netlify copy hides Netlify's badge.** Netlify injects a script into every page it serves that draws a "Powered by Netlify" badge in a fixed iframe over the bottom-right corner, where it covers the game. Its own "Hide this badge" button remembers the choice for one device only. `tools/deploy_netlify.sh` now adds a style to `index.html` that hides the badge's iframe (`#nl-badge-frame`) and the owner toolbar's (`#nl-hud-frame`). The itch.io build is unchanged.
88. **The web build offers new versions as soon as they're deployed.** Godot's service worker serves the game from its cache, and a new worker waits until every copy of the game is closed, so a deploy reached a Home Screen player only on the second launch after closing the app, which iOS rarely does. `WebUpdate` (an autoload, web only) checks for a new worker at start, every 30 minutes and when the page is shown again. Once one is waiting, a bar at the top reads "New version ready" with Later and Update. Update saves, asks the waiting worker to take over, and reloads into the new version; Later hides the bar until the next launch. `tools/export_web.sh` adds the `skip-waiting` message listener to the exported worker, since Godot's has none. A test served three builds in turn: mid-game the bar appeared, and Update saved, reloaded and ran the newest build. On itch.io each upload has its own URL, so the next page load already gets the new version and the bar doesn't appear.
